# 采购承接与知识版本修复

本次落实代码评审中的承接一致性、草稿隔离、知识版本、同步阻塞、重试和便携包交付。

## 联网承接

采购端保存待确认记录，再请求门户核对当前目标价和采购方看到的接受回执。门户核对最新回复并冻结后返回确认。若供应商已更新回复，采购端拉回最新记录，并提示重新核对。若请求超时，待确认记录会保留，点击继续确认可重用原请求编号。门户确认和本地提交之间发生中断时，重试可取回原确认。

工作台和独立门户需同时升级。待确认期间，采购端不能另选供应商或修改本单。应先恢复原门户连接并完成确认。冷备份或设备迁移如涉及待确认记录，应保留原数据库和原门户，完成确认后再切换。

日常同步与承接确认的 HTTP 请求均在本地事务外执行。日常同步回写前核对项目版本，若期间发生编辑，需要重新同步。正式发布和收件仍由采购人员触发。

## 表单与知识版本

切换询价和新建询价时重置报价、选择依据和费用变更输入，目标条款默认取本单的需求条款。发布新目标价后清除上一版的金额草稿和承接理由。供应商页面在同一页面内重试相同内容时复用提交编号。刷新或关闭页面会结束当前重试上下文。

首次知识审核发布原版本，后续修订通过同一发布入口更新主表和历史。首次审核 V1 后，待审 V2 可以继续发布。旧库历史不自动改写。可先导出核对产品主表的当前正文和同编号历史正文，并关注主表已审核但历史仍为待审的同编号记录。确认真实依据后创建新修订并发布，再核对有关待发回复。

以下只读查询可在备份库上定位这类旧数据。结果需要人工核对，不能据此覆盖历史。

```sql
SELECT p.tenant_id, p.id, p.sku, p.version, v.status
FROM products p
JOIN knowledge_versions v
  ON v.tenant_id = p.tenant_id AND v.product_id = p.id AND v.version = p.version
WHERE p.review_status = 'verified'
  AND (v.status <> 'published'
    OR json_extract(v.content, '$.name') IS NOT p.name
    OR json_extract(v.content, '$.summary') IS NOT p.summary
    OR json_extract(v.content, '$.source') IS NOT p.source);
```

重复保存相同需求与资料引用不会使回复重新待审，实际修改字段值、确认状态、来源或资料版本仍会使先前审批失效。

## 交付与验收

便携包在 `scripts` 子目录内提供备份和恢复脚本，包根目录附操作说明。验收先使用独立数据目录，真实业务库和另一台 Windows 电脑仍需现场验证。供应商主档编号、报价后撤回和持久化自动同步队列属于后续迭代。
