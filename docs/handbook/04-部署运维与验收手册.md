# AI WorkHub 部署运维与验收手册
2026年11月10日　面向部署与试点负责人　基线 a1fa1f7

本手册用于分清线上演示、本地工作台和在线供应商门户，并在每次发布后留下可复查证据。当前提供 Windows 便携体验包方案，尚未完成另一台干净电脑和公开门户的生产验收。使用默认演示账号的包只作测试，不作为正式业务账号交付。

## 1 三种部署形态
形态｜运行与存储｜验收重点
Pages 演示｜静态站点和 localStorage｜无 /api 请求、刷新保留、模拟身份与真实身份清楚区分
本地完整服务｜Java 加内置前端和 SQLite｜重启保留、权限隔离、真实状态检查、备份恢复
公开供应商门户｜独立 Java 服务与独立 SQLite｜HTTPS 可达、门户模式、邀请隔离、同步一致性

## 2 Windows 体验包
scripts/package-windows.ps1 接受 -RuntimePath，要求该目录存在 bin\java.exe。开发者准备可分发运行时与依赖缓存；脚本构建前端、执行后端离线打包并复制 runtime 与 jar，输出 release 目录及 ZIP。运行时授权与完整性由交付者核对，不能只把 java.exe 单独复制。

打包前清除构建模式歧义：设置 VITE_DEMO_MODE=false、VITE_BASE=/。脚本当前未主动重置这些环境变量，终端残留 Pages 设置会导致错误模式，需要在发布清单中检查。包内 frontend/dist 应是刚构建的真实版。

用户解压完整 ZIP，双击启动工作台.cmd，脚本通过包内 Java 隐藏启动服务，绑定 127.0.0.1:18081，健康检查后打开浏览器。停止用停止工作台.cmd。不能把本机地址发给异地供应商，也不能认为手机访问电脑的 127.0.0.1 就能连接。

数据目录为 %LOCALAPPDATA%\AIWorkHub，包含 workhub.db、portal.properties、startup.log、error.log 和 process.id。卸载程序目录不自动删除业务数据。删除或重置库前必须有备份和明确业务授权；排障不得默认删库。

## 3 门户配置与收件验收
门户与客户端运行同一服务版本，使用不同数据库。门户启用 procurement.portal-mode=true 与至少 32 字符的随机 procurement.relay-key，采购端 portal.properties 设置 procurement.portal-url=https://实际地址 和相同 relay-key。密钥不得放前端变量或分发给供应商。

PortalBoundaryFilter 负责门户模式 API 边界。验收时从未登录公网请求内部登录、工单、采购管理和导出接口，必须拒绝；供应商凭指定邀请只能读本家报价及回复。验证缺少邀请、伪造邀请、其他需求邀请和缺少共享密钥均失败。

完整链路为本地创建需求、邀请供应商、同步发布、供应商在另一设备报价、本地拉回、到期关闭、再次最终同步、比价、发布目标、同步、供应商回复、拉回并确认承接。任何上传或拉回失败应显式显示失败，不能把本地已生成目标当作门户已收到。

现行没有一键公网部署脚本或可靠后台同步队列。公网域名、HTTPS 证书、反向代理、网络限制、数据保留和日志脱敏须由部署方落实并验收，不应临时把内部默认服务直接开放。

## 4 备份和恢复操作设计
现行没有完整备份恢复管理 UI。临时运维策略为停止服务并确认进程退出，再复制完整数据目录到受控备份位置，记录服务版本、时间及文件校验值。若使用 WAL 等模式，需一并处理相关文件，不能在运行中只复制 db 后宣称一致。

在新隔离目录或测试电脑恢复，不先覆盖唯一原库；运行同版本服务，核对企业数、项目数、最后报价、承接和变更记录、权限及登录。通过后再按发布计划切换，旧副本保留直到验收结束。数据备份与 portal.properties 密钥备份应限制访问，不随公共文档分享。

设置页 JSON 导出不包含完整账户、会话和全库状态，也未纳入完整采购备份，不能直接作为灾备恢复文件。后续应增加在线一致性备份、恢复预检、版本迁移和回滚演练。

## 6 常见排障
启动失败先查 startup.log 与 error.log、端口占用、运行时是否完整、数据目录是否可写；不要为排障关闭权限或删数据。Pages 白屏先检查资源路径与构建 VITE_BASE，真实版出现 /api 404 则核查代理、端口及是否误开门户模式。

供应商打不开链接先区分模拟链接、本机链接与公开 HTTPS 链接；提交后看不到，检查是否已同步、邀请是否对应项目和轮次、截止是否到期。版本冲突先重新读取，避免重复创建业务操作。金额不一致检查最后版本、附条件排除及是否误把参考当整单价。

每次发布保存提交号、构建模式、测试结果、包校验值、配置变更、备份位置、验收人与回滚说明。文档日期与版本变化时同步更新本套 Markdown 和 Word；旧方案保留作历史，不覆盖已形成的业务证据。
