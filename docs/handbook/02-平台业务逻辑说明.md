# AI WorkHub 平台业务逻辑说明
2026年11月10日　业务与测试参考　基线 a1fa1f7

平台同时服务客户咨询处理和采购询价。客户侧输出经过审核的回复及跟进结果，采购侧输出供应商明确接受的整单方案及履约记录。两条流程共用企业身份、资料与审计概念，但没有实现订单、库存、支付或自动发消息系统。本文件先说明现行行为，再明确后续建议。

## 1 企业与身份边界
企业配置来自 frontend/src/workflow/profiles.json，现有 Kotech、Warmpaca 和上海安特瑞三个工作空间。客户原话与业务录入不会因界面切换语言而自动翻译。上海安特瑞的润滑油贸易配置为暂定背景，不是已核实的公司产品档案。

角色｜现行主要职责与限制
SALES｜处理负责或明确授权的客户工单；不能访问采购管理
REVIEWER｜技术承诺和知识审核；因审核关联获得工单访问
MANAGER｜商务与售后承诺审核；可访问本企业采购管理
ADMIN｜账号相关管理权限与业务导出；不自动获得所有承诺类业务审批资格
供应商邀请持有人｜通过邀请秘密查看指定需求并提交本家报价和回复；不是实名账户

真实模式登录签发服务端会话，前端 token 保存在 sessionStorage。每次业务请求使用当前企业上下文；切换企业、跨企业访问及旧 revision 都要由服务端验证。Pages 允许模拟切换身份，这不是多人认证或安全隔离。

## 2 客户咨询闭环
接收原话后选择企业场景，填写需求字段的值、状态及来源。状态区分缺失、待核实、已确认。确认必须有值与来源，不能只勾选完成。引用当前企业已审核知识后保存回复草稿，选择澄清、技术、商务或售后风险类别。

澄清回复由负责人自检；技术承诺进入 REVIEWER，商务及售后承诺进入 MANAGER，高风险不得作者自批。系统依赖填写者正确声明风险，尚无自由文本承诺自动识别。

审核绑定当时需求和资料快照。需求或依据变化使未发送审核失效；知识版本更新或撤回后，复制核准正文与发送登记会再次检查。复制不等于已经发送，dispatch 只登记在外部实际发送的渠道和时间。

## 3 跟进与知识发布
工单状态包括待处理、处理中、等待客户、等待内部和已完成。进入等待状态要有跟进任务；任务记录执行人、到期时间和时区。完成或取消任务需要结果说明。结案前必须处理未完成任务与待审回复，重开须说明原因。

知识修订创建独立版本，旧有效版在新版本发布前继续使用；新修订需要非作者审核。撤回后不能作为新承诺的有效依据。知识修订、有效期自动管理和规则迁移是不同能力，后两项仍待开发。

场景｜必须特别核实的信息｜承诺输出限制
Kotech 固定设备｜工况、压力气量单位及基准、电源、数量和交付地｜技术参数以有效资料为据
Kotech 备件｜型号序列标识、原件号、数量、铭牌来源｜无识别依据不确认适配
Warmpaca 零售批量｜SKU 变体、包装、数量、可售核验、到达时间｜无库存接口不承诺实时库存
Warmpaca 售后｜外部订单引用、批次、问题与政策版本｜受理记录不等于退款执行
上海安特瑞指定产品｜完整品名规格、包装单位、交付与报价口径｜主营和授权待确认
上海安特瑞替代核验｜原用油、厂家要求、工况和技术资料｜相似名称不证明可替代

## 4 采购需求与收件
真实后端创建需求时直接冻结发布；演示有草稿确认页面。需求含名称、运输路线、货量、统一条款、截止时间与费用科目。首版按 CNY 同口径整单金额填写，不支持任意混合单位计价。

每次邀请产生独立秘密，链接 fragment 携带秘密，请求使用 X-Invitation。数据库存哈希，链接只在生成时显示。持有人能代表该邀请操作，因此必须把链接视为授权凭证；撤销重发与实名校验仍待开发。

Excel 导入支持单列金额或名称金额双列；双列按准确名称匹配。拒绝缺项、重复、未知科目、负报价和超过两位小数。带入表单并不自动提交。供应商报价每次提交保留新版本，正式比较取最后一版；附加条件保留且从自动最低价组合排除。

===
## 5 比价与反向议价
真实后端需到截止时间后关闭轮次；演示允许手动模拟到期。独立门户场景在关闭后仍需同步收齐回执，才允许比较。每项在无附加条件的最新报价中取最低值，形成参考组合，并保留来源；最低整单另外计算。

示例十项费用的最低整单为 3680.00，分项参考为 3410.00。参考组合没有任何一家完整承诺，不能直接发订单。采购方核对目标金额和整单条款后发布，供应商分别明确接受、拒绝或附条件接受。只有当前目标价的最新明确接受能用于承接，旧目标价或附条件回复不算。

演示已自动带入最低价和原条款，本地真实管理页仍有逗号输入目标金额等简化交互，未完全复用模拟页面。模拟报价草稿会按企业及供应商保留，真实门户尚未承诺具有相同草稿恢复能力。

## 6 承接与变更
确认承接后，可登记费用申请、双方确认依据、完结或承接后退出。申请金额和核准金额分开，减少填负数；费用变更不自动判定供应商责任，应记录客户新增范围、现场异常或漏报价等原因。

现行演示阻止待核准变更下完结，并在退出或完成后阻止进一步履约修改。真实后端的这些转换约束尚未全部对齐：后续开发应以设计文档 R1 清单补齐，不应把页面按钮限制视为 API 保证。

## 7 数据所在位置
Pages 数据只在当前浏览器，可按企业空间区分；重置或载入样例前归档已发布进度，清理浏览器会失去历史。跨设备供应商无法通过模拟链接汇总报价。

完整服务主数据在 SQLite，便携包存于 %LOCALAPPDATA%\AIWorkHub。独立门户有自己的数据库；本地同步发布需求、费用、邀请和目标价，拉回报价与回复。内部工单、审计及费用变更不属于当前门户上传范围。当前同步为手动操作，不是持续后台同步。

## 8 看板和供应商档案口径
指标｜现行口径｜解释边界
询价项目数｜当前项目及归档或本企业数据库项目数｜演示草稿也计项目，但不计邀请
报价回收｜每项目每供应商有报价计一次｜修订只增加版本数，不重复计回收
已确认承接金额｜所有获选目标价之和｜包括后来退出的原承诺，不等于支出
核准增减费用｜approved 变更金额求和｜申请不计入，不等于已结算
目标价接受率｜每轮目标价最新回复为 accept 数除以目标邀请数｜未回复进分母，附条件不计接受
完结费用变更率｜有核准变更的完结单除以完结单｜履约中不进分母，不自动归责
承接后退出｜已获选且登记退出的项目数｜不等于报价后撤回，后者待开发

供应商档案按名称跨项目归集，包含报价版本、费用明细、目标回复和履约变更。现有主档没有统一企业身份编号，同名合并与别名分散均可能存在。管理员在评价前应核实企业主体，不能依据单个样本自动排名或封禁。

供应商档案的截止报价回收按已关闭或截止到时判断；普通台账显示当前回收总量，两者分母并不相同。历史采购 metrics API 和新前端档案分别计算，后续应统一统计服务与时间窗口。

## 9 人工责任与未接入能力
业务员确认客户需求及来源；审核人核准职责范围内的承诺；采购方确认目标与获选方；供应商明确接受整单；双方确认变更；管理者核实异常归因。最低价计算不替代这些责任。

平台当前没有真实模型调用、自动外发、附件 OCR、实时库存、自动采购订单、收付款、发票或完整结算。现有审计可追溯操作，但不是能抵抗本机管理员修改的独立证据链。

依据目录：frontend/src/workflow 与 procurement；后端 WorkflowService、KnowledgeVersionService、ProcurementService；schema.sql；docs/V3-development-status.md 及采购说明。业务变更应同时更新本说明和对应测试。
