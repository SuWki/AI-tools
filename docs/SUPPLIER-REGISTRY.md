# 供应商档案与承接前撤回

采购端在「登记供应商编号」建立档案。发布新邀请时选择已有编号，同一编号可跨询价复用，在同一询价中最多邀请一次。首次邀请也可直接填写新供应商名称，由系统生成编号。确认确为不同主体时才为同名供应商分别登记。

已有邀请未写入档案编号时，在项目详情先选定档案，再点击关联。关联保留原邀请名称、报价和回复。未关联的历史邀请独立展示，系统不会按名称推断身份。同一项目若已有两个历史邀请，不能同时关联到同一档案。档案编号只保存在采购端。

供应商提交报价后、采购方确认承接前，可以填写原因并撤回整轮报价。撤回保留原金额、回执、备注和接受记录。从撤回起，本邀请停止报价与议价回复，已撤回报价从可比最低价候选中排除。承接后的退出仍按履约异常登记。

独立门户场景下，采购方同步后可看到撤回时间、原因和记录。门户会在确认承接时再次校验撤回状态，即使采购端还显示旧接受记录也会拒绝承接。同步后应重新比价并核对已发布目标价。已发出的目标价保留原版本及条款，由采购方决定是否重发。本地与独立门户需要同时升级。

档案分别展示历史目标价接受率、承接前撤回和承接后退出。接受率仍按每轮最新回复计算，报价回收仍统计已收到的历史报价。若目标是查看当前可用报价，使用比价结果的排除项。GitHub Pages 用样例数据演示撤回和档案统计，真实档案写入本地 SQLite。
