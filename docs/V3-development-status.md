# V3.1 开发与验证记录

2026-11-05。基于三企业设计实现第一版业务闭环。此记录描述实际交付范围，设计稿仍包含后续能力，不应把整个设计包视为全部已实现。

## 已接入真实后端

- Kotech、Warmpaca、上海安特瑞三企业名称和各三种场景。单一 JSON 配置供后端规则验证和前端表单共用；上海安特瑞仍明确标记主营品牌及产品资料待核实。
- 工单工作区：原话、场景、逐工单需求值/确认状态/来源、当前企业已审核资料引用、可编辑回复草稿及版本、人工核对/授权审核、复制核准正文、外部实际发送登记、跟进任务与执行结果、时间线、状态/阶段、分配和结案/重开。
- 审核绑定资料与需求快照。保存需求或引用变化使未发送审核失效；资料发布新版本或撤回后，正式复制/发送登记再校验，旧引用无法绕过。
- 普通澄清由负责人自检。技术承诺需 REVIEWER，商务及售后承诺需 MANAGER；高风险内容不能由作者自批，ADMIN 不自动成为业务审批人。依赖提交者正确声明风险，不宣称自动检测所有自由文本承诺。
- 任务含执行人、到期时间、原时区；工作台汇总本人的未完成任务和待审回复。等待状态需有跟进，结案需处理未完成任务与待审回复。
- 知识修订保存独立版本；原有效版本在新修订发布前继续使用，新修订须非作者审核。支持历史正文及撤回。
- 当前企业按成员校验；销售默认只见本人负责或明确分配的工单，审核人与任务执行人获关联工单访问。未分配的管理者可查看汇总，不自动获得工单原话。
- 会话 12 小时有效，切换只修改当前 token，退出撤销服务端会话；业务请求携带预期企业上下文，变化时拒绝旧上下文请求。浏览器 token 改为 sessionStorage，各标签可独立登录。
- 保存带乐观版本检查；过期版本拒绝覆盖。重要操作写入企业审计，设置页支持管理员/管理者查询；明细导出仅 ADMIN，包含工作流并记录审计。

## 兼容与数据

新增 case_workflows、case_access、knowledge_versions 表，不删除旧表或旧业务数据。默认演示企业仅在原通用名称仍未修改时升级为实际名称，补齐演示审核账号的三个企业成员关系。既有知识没有历史快照时，从当前版本起建立记录，无法恢复此前未保存的内容。

隔离预览使用 backend/data/workhub-v3-preview.db，避免改动已有演示数据库。GitHub Pages 的浏览器演示支持新工单工作流，但不提供真实身份隔离或多人安全；知识修订/发布/撤回及审计查询需要后端版。两种模式的能力边界在页面说明。

## 验证方法

前端执行 npm run build。后端执行 mvn test / mvn package，新增 WorkflowIntegrationTest 使用 SQLite 共享内存数据库，不修改用户数据。

测试覆盖：澄清回复到任务/结案/重开；承诺类必填/来源/依据/授权审核；版本冲突；跨企业与未分配工单访问；旧接口不能绕过结案；当前会话切换/退出/过期；三企业配置；知识修订发布后旧依据无法正式复制。

验证结果：7 项后端集成测试通过（0 失败、0 错误）；前端 TypeScript 与 Vite 生产构建通过。后端生成 workhub-backend-3.1.0.jar。

浏览器实测：管理员登录；Kotech 需求字段保存、澄清草稿 V1、人工核对与发送登记、创建含 Asia/Shanghai 时区的跟进任务；切换 Warmpaca 后专属字段显示正确，中文输入在英文 UI 中保持原文；切换上海安特瑞后正确显示企业名称、润滑油场景及待核实提示。检查桌面和窄屏布局，窄屏主文档没有横向溢出（导航可横向滚动）。已修复备用预览端口的 CORS 限制和旧需求清单的中文字段读取问题。原生日历的自动化填值需通过键盘触发变更，实际创建任务已成功。

浏览器验收数据明确标为测试内容，仅写入独立预览数据库。截图保存在 docs/screenshots/workhub-v3-browser.png。浏览器仅完成以上抽查，不等于全部设计场景已逐项验收。

## 本地预览

此轮独立预览地址：http://127.0.0.1:5174，后端 18080。账号 admin@workhub.demo / demo1234；技术审核 reviewer@compressor.demo，商务审核 manager@compressor.demo，密码相同，两者可切换三个演示企业。

启动后端：在 backend 中执行 `java -jar target/workhub-backend-3.1.0.jar --server.port=18080 --spring.datasource.url=jdbc:sqlite:data/workhub-v3-preview.db`。

启动前端：在 frontend 中先设置 PowerShell `$env:VITE_API_TARGET='http://127.0.0.1:18080'`，再执行 `npm run dev -- --host 127.0.0.1 --port 5174 --strictPort`。
