## 具体问题

1. backend/src/main/java/com/aiworkhub/auth/AuthService.java 的 switchTenant 使用 `UPDATE sessions SET tenant_id=? WHERE user_id=?`，会改变同账号其他设备的工作空间。另一设备 UI 仍显示旧企业时，后续请求可能落入新企业。应只更新发起请求的 token 对应会话，并验证双会话互不影响。
2. frontend/src/App.tsx 的 logout 仅清除浏览器 token，服务端会话未撤销；服务端查询会话也没有过期时间条件。需要补充退出接口、过期校验与对应验证。
3. frontend/src/api.ts 区分真实 API 与浏览器演示 API；.github/workflows 中 Pages 构建明确设置 VITE_DEMO_MODE=true。因此 Pages 产物是静态本机演示，不能用它证明后端企业隔离或多人共享有效。本次未检查线上部署状态。
4. 当前工作区有大量未跟踪的前后端文件和已修改 README，尚未形成完整 Git 提交交付；本次没有提交或推送。

## 建议实施顺序

1. 修复会话切换范围，并验证同账号两次登录后切换企业互不影响；补充退出撤销与过期机制。
2. 完成逐工单需求字段、缺失项记录，再据此生成可编辑回复草稿，保存人工审核结果。
3. 将跟进备注扩展为带到期日、执行人及完成状态的任务，支持负责人和阶段维护。
4. 补齐知识内容版本、复盘关联、后台配置及实际耗时统计。
5. 使用两个企业与不同角色完成隔离、权限和一条咨询从登记到完成的端到端验收。

不接模型 API、WhatsApp、OCR、自动报价均符合设计方案首期边界，不应优先于上述闭环缺口。
