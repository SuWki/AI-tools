# R1 采购可靠性第一批交付

2026-11-11。本次落实维护文档 R1 的第一批，未宣称 R1 所有退出条件已满足。

## 已实现

- 真实服务在已完成或已退出后拒绝变更申请、批准、重复完成和退出；有待确认变更时拒绝完结。已承接后拒绝新的目标价。
- 供应商新的回复在已承接后被冻结；相同 requestId 的重试仍可读取原回执。拒绝和附条件回复必须填说明。
- 门户同步增加 responsesFrozen 布尔标志，门户收到后停止新回复；不上传内部承接明细、退出原因和费用变更。采购端获选后不再用后续门户收件覆盖报价和承接所依赖回复。冻结标记仍依赖手动同步，未实现瞬时跨设备冻结或后台队列。
- 供应商页面收到冻结标志后展示原因并禁用回复按钮。
- Windows 打包强制 VITE_DEMO_MODE=false、VITE_BASE=/，前端构建后还原调用者环境变量，避免误打静态演示包。
- 增加停服冷备份和恢复到新目录的 PowerShell 工具；SHA256 清单、SQLite 文件头校验、拒绝覆盖已有目录，恢复时锁住备份源文件防止校验后被改写。

## 备份恢复使用

先关闭所有 WorkHub 实例。以下路径按实际修改，不要在运行时复制 SQLite：

```powershell
./scripts/backup-data.ps1 -DataDirectory "$env:LOCALAPPDATA/AIWorkHub" -BackupDirectory 'D:/Backups/WorkHub-20261111'
./scripts/restore-data.ps1 -BackupDirectory 'D:/Backups/WorkHub-20261111' -NewDataDirectory 'D:/Backups/WorkHub-restored'
```

工具只备份 workhub.db，不复制 portal.properties、会话日志或共享密钥；配置另行受控保管。存在 SQLite sidecar 时拒绝备份，须先正常停服。恢复只创建新目录，不自动切换生产数据、不删旧目录；用同版本服务在隔离环境核对数据后再按运维流程切换。清单不替代逻辑完整性校验，也未提供跨应用版本迁移。
