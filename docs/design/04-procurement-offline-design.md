# 采购询价 反向议价与离线部署设计

需求草案 · 2026-11-05。基于用户新增采购场景编制，本轮形成业务与部署方案，未修改业务代码、未向供应商发送邀请。用户已确认供应商在线填报、采购电脑可以联网同步、主数据保存在本地。正式采用本地采购客户端与在线供应商门户，局域网/离线文件交换作为备用模式。

## 1 产品结论

新增独立“采购询价”模块，复用企业、账号、权限、资料版本与审计。采购单独建模，关联现有客户工单，但不能把供应商出价塞进销售回复草稿。

核心链路：发布冻结需求和费用模板 → 邀请供应商 → 供应商独立报价 → 截止开标与同口径比价 → 生成目标价版本 → 授权后发出反向议价 → 供应商逐项/整单接受或提出条件 → 确认完整承接方案 → 履约与变更 → 供应商评估。

各科目最低价之和是“分项最低参考价”，只有当供应商接受同一范围、同一条件下的完整价格，或采购明确允许分包且各段衔接可行时，才能形成“可执行报价”。不能把参考价自动当作订单成交价。

## 2 离线环境的三种含义

| 模式 | 供应商如何填写 | 数据位置与限制 |
|---|---|---|
| 不连互联网，连接局域网 | 采购电脑开启局域网填报，供应商设备在同一可达网络扫码打开 | 主数据在采购电脑，供应商浏览器持有其填写内容；电脑需在线、不能休眠，二维码地址对外网供应商不可达 |
| 完全无网络连接 | 每供应商导出一份离线报价包，填写后导出回执，通过允许的介质带回导入 | 无法扫码访问另一台电脑；只能做文件往返。不能把文件校验码称为已验证供应商身份 |
| 采购数据本地为主，供应商远程在线 | 另设联网收件门户，报价同步/人工导入本地 | 门户必然接触报价，不能承诺数据从未上网。须单独确认数据边界，首版不默认采用 |

仅采购电脑离线但供应商可联网，与“所有参与者完全离线”不同。邮件、网盘或聊天软件传文件也会经过联网系统，必须按实际业务授权选择，不能宣传成完全不联网。

用户已确认采用第三种模式：公开可达的供应商门户收件，采购客户端主动联网同步，本地为采购主库。门户仍需暂存需求、供应商报价和回复，不宣称所有数据从未上网；具体分布与同步约束见第 13 节。局域网与离线文件包保留为备用，不作为默认供应商入口。

## 3 一次需求与十项费用模板

### 需求头

采购企业、需求编号、运输起点/终点（足够报价的区域，非必要个人地址不公开）、货物类别、数量、重量、体积、件数及单位，起运/交付日期窗口，装卸条件、服务范围、运输限制、是否允许分包、报价截止与时区、报价有效期、币种、税费/发票口径、结算条件、联系人角色。

由采购确认具体适用字段；数量未知允许草稿保存，但必须在正式询价前说明估算基准与允许偏差。危险品等特殊货物的实际承运要求由企业人员确认，本设计不自动判断其运输资质。

### 十项费用示例

提货、起点装卸、起点仓储、干线运输、中转、终点仓储、终点装卸、配送、保险、其他约定服务。此列表只是模板示例，不是固定业务真相；实际项目可改为适用的十项科目。

每个科目有稳定编号、名称、服务边界、计价方式（整单/吨/立方/公里/天等）、基准数量和单位、是否必报、税口径、能否拆分、关联包组及说明。不同路线或需求可复用模板，但已发布轮次保留不可覆盖快照。

报价数据逐项区分：有价（允许明确的 0）、包含在某科目、明确不适用、无法承接、未报价。空白不能当 0；包含项必须指向对应科目。数量阶梯、最低收费、等待免费期、超期费和组合折扣属于价格条件，不能丢到无结构备注里。

提交页展示供应商自行核对的整单总价、税费、适用数量和条款；十项金额全部填写并不代表业务范围一定完整，仍需核对包组和排除项。

## 4 供应商邀请与提交

一个采购需求可以有公共说明，但每家供应商有独立邀请码/邀请链接，报价不允许凭同一个公共二维码选择任意供应商名称提交。邀请的公开编号用于定位，随机秘密用于权限；秘密只存哈希，支持到期、撤销与重发，不写入普通访问日志。

链接只含访问所需标识，不能直接编码报价、客户资料或数据库路径。供应商仅能读取本次需求和自己的报价/回执，看不到其他供应商身份、金额与目标价来源。

首版二维码/链接由系统生成，采购人员在获批准渠道中分发，不自动发送邮件或消息。局域网供应商入口与内部管理接口分开鉴权；局域网加密传输、证书信任及只开放所需端口要在部署时实际验证，不能因“内网”就取消身份校验。

供应商先保存本地临时输入，再提交冻结的报价版本。正式提交包含需求版本、模板版本、供应商身份核验状态、逐项金额、排除条件、总价、有效期、提交人声明及时间。平台返回唯一回执号和内容摘要。修改生成新报价版本，不覆盖历史，按截止前最后有效版参与比价。

已发布需求改了路线、货量、服务范围、币种等比较基础时生成新需求版本和新轮次，通知全部有效受邀者重新确认；禁止只对某家私改比较口径。截止后的补充报价单独标记，是否纳入须有统一规则和批准记录。

## 5 比价与反向议价

### 5.1 同口径规则计算

报价按需求版本、业务范围、币种、税费、数量、有效期、运输/服务条件、排除项等形成可比组。默认不自动换汇；如确需换汇，采购须录入经授权的汇率及日期并形成固定快照。金额使用精确十进制或最小货币单位，不用浮点近似。

每项最低价只从通过校验、未撤回、可承接且条件相同的有效报价中选择。缺项、捆绑优惠、包组、阶梯量和最低收费不允许拆开直接取最小值。异常低价提示核验，不自动认定供应商有问题，也不默认剔除。

输出同时展示：最低完整整单价；十项最低参考组合；每项来源报价版本（仅采购授权人可见）；不可比项及理由；包组与衔接约束；候选方案的执行差额。

### 5.2 一个必要例子

同一整单只比较两项，A 为 100+300=400，B 为 200+150=350。分项最低参考价为 100+150=250，但没有任何一家报过整单 250。

反向议价可向符合条件的供应商提出整单 250 的目标，供应商可能接受、拒绝、附条件接受或另报完整总价。在其接受前，界面只显示“目标价 / 待供应商确认”，不能显示“已节省 100”或生成订单。十项情形遵循相同规则。

### 5.3 反向报价版本

系统可自动算出参考组合并准备议价草案。采购授权人核对完整范围、总价、付款、时间和条件后发布目标价版本。供应商收到的是本次完整目标价和必要条款，不显示其他供应商明细或最低价来源。

默认要求供应商确认整单承接；允许分包的需求另按服务段确认，核对交接责任、额外接驳费和各段可行性。不能只收集十个分项“接受”勾选就视为一个供应商愿意承接全单。

回复状态为：待回复、整单接受、拒绝、附条件接受、重新报价、超时。附条件接受进入条件核对，不能自动等于接受；明确总价、各项费用、服务范围和条件都一致后才记为有效接受。

选定供应商需有选择记录。系统给价格与履约证据，采购可选择非最低价方案，但必须说明服务、风险、时效或其他可核验理由。订单确认与合同承诺仍经企业授权，不由模型自动决定。

## 6 AI 的位置

十项最低价、总价、差额和比率使用确定性规则，无模型、无互联网也能运行；不把取最小值包装成 AI 推理。

AI 可选用于把非结构化需求整理成草稿、识别排除条件、提示不可比费用、总结供应商记录及准备议价说明。提取内容要显示原文来源，由人确认结构化字段；模型不能擅改金额、删除不利报价、判断供应商违约或替人批准成交。

基础离线安装包不含大模型，不要求显卡。若日后需要离线语言模型，另交付可选模型包，并针对客户电脑测量内存、磁盘与速度；模型不可用时完整流程仍可操作。

## 7 供应商评估的指标口径

| 指标 | 定义与分母 | 不混算的情况 |
|---|---|---|
| 邀请报价响应率 | 提交有效报价的邀请数 / 已送达且已到截止的邀请数 | 未送达、撤销需求单列 |
| 目标价接受率 | 无未解决条件的有效整单接受次数 / 已送达且结束的目标价邀请次数 | 拒绝、超时、附条件待核验分别展示；不称履约接单率 |
| 报价后退出率 | 有效报价后供应商主动撤回的次数 / 有效报价机会数 | 买方改范围、双方取消与未被选中单列 |
| 接单后退出率 | 确认承接后因供应商原因退出的承接单数 / 有足够观察结果的已承接单数 | 需原因认定与证据；进行中的单不算成功或失败 |
| 费用变更发生率 | 履约中至少发生一次核准费用变更的单数 / 本期已完成承接单数 | 在途变更另显示；一次单有多次变更仍计一单 |
| 费用变更幅度 | 同范围已核准费用净变化 / 初始确认金额 | 初始金额为 0 显示不适用；绝对涨价、降价与需求范围调整分列 |
| 价格竞争力 | 同口径比价组中相对有效报价中位数/基准的差额及样本数 | 不跨路线、数量、日期或服务范围直接排名 |

费用变更必须记录提出方、原因类别（需求变化、现场异常、漏报、供应商原因、其他）、事实依据、原金额、变动金额、版本及双方确认。发生异常不自动归责供应商；归因不明显示未认定。实际结算记录与核准变更分开，未经批准的加价只能作为申请。

先显示原始指标、分母、观察期间与证据，不急于给单一总分。样本很少显示样本不足；如启用评分，公布权重与规则版本，保留各维度，不让低报价掩盖退出和加价风险。

## 8 降低人为控价与保证可追溯

发布需求、回收报价、截止开标、可比性判定、计算参考价、发布目标价、供应商回复、选择与履约变更都形成事件记录。事件包含操作者、角色、来源渠道、电脑时间/时区、数据版本、内容摘要和前后版本关系。离线电脑时钟可被改变，接收顺序与版本号用于辅助判断，不能单凭本机时间证明绝对先后。

采购录入者不能改写供应商已提交的金额；补录报价须标“采购代录”、附原件来源与供应商确认，不能伪装成供应商自填。剔除、改口径、延截止或选择非最低完整价都要留原因。默认在截止并经授权开标后统一展示报价；若采用密封报价，需要独立开标密钥、双人职责和报价凭证设计，不能仅隐藏页面就声称密封。

数据库与附件仅允许业务程序通过权限接口写入。事件可追加并形成摘要链，定期导出审计快照给独立保管人，与供应商自己的回执交叉核对。摘要链只能帮助发现修改；电脑管理员同时掌握数据库、程序和密钥时仍可能重造记录。完全单机不能承诺“杜绝人为干预”或第三方不可抵赖，需要独立凭证或外部见证提高证明力。

## 9 无环境电脑的交付方案

推荐 Windows 本地安装包：React 静态前端 + 已构建 Java 服务 + 随包运行时 + SQLite + 本地启动器，并内置连接供应商门户的出站同步模块。安装和本地分析无需互联网，收取新报价与发布议价需联网。用户只安装/解压并双击启动，不安装 Node、npm、Maven、JDK、MySQL 或 Docker；首次启动自动初始化自己的空业务库，示例数据须明确选择，不沿用演示默认口令。

现有前端生产包由后端提供，实际运行不启动 Vite。Java 服务的运行时随包交付，打包构建机可使用 jpackage 生成 Windows 应用镜像或安装包；具体 JDK/运行时版本须针对现有 Spring Boot 与 sqlite-jdbc 做兼容性测试后冻结。安装包不能只包含 jar 后让用户自己装 Java。

Oracle 文档明确 jpackage 可打包 Java 运行时，用户无需另装运行时，并提供 Windows 应用镜像及安装格式：[jpackage 打包概述](https://docs.oracle.com/en/java/javase/21/jpackage/packaging-overview.html)。SQLite 无独立数据库服务进程，不需要用户另行安装数据库服务：[SQLite 无服务器架构](https://www.sqlite.org/serverless.html)。这两点支持此交付设计，当前项目尚未产出该安装包。

### 启动器负责什么

单实例锁、端口冲突检测、启动服务并等待健康、打开默认浏览器、托盘/退出提示、日志查看、备份入口。服务绑定 127.0.0.1 为默认；用户明确打开局域网填报才监听选定网卡，展示实际可达地址与连接自检。管理页不因开启供应商入口就免认证。

采购电脑关机/休眠时无法接收网页报价；界面发布前提示可用时段并检测网络变化，IP 改变后重新生成入口。若要供应商全天可填，需要常开的局域网主机或经批准的联网收件服务，不能承诺一台关机电脑可接单。

### 本地数据与升级

程序装在程序目录，数据存独立可选目录（如用户目录的 AIWorkHubData），包含 workhub.db、附件、审计与配置；不把业务库放在安装目录，也不随升级覆盖。SQLite 文件由一台主机上的服务独占管理入口，不能放共享盘让多台电脑直接各自打开写入。

供应商网页只向主机服务提交，不直接接触数据库。多个企业分开数据权限与邀请范围；供应商使用独立外部身份，不能给内部成员账号。

备份由应用发起一致性快照，包含数据库、必要附件与清单，不能在运行时简单只拷主 db 而遗漏未合并日志。备份加密及恢复密钥分开保管，定期演练恢复；单机数据损坏不能只依赖同一硬盘上的备份。

升级使用离线包校验、升级前自动备份、版本化迁移、失败恢复。迁移后旧程序不兼容时不得直接覆盖运行。安装包签名与运行时再分发许可在交付时核查，断网目标机实际测试后才称为可离线安装。

## 10 完全离线报价包

每份包包括冻结需求、费用模板、供应商邀请标识、填报说明与可离线打开的表单；供应商填写并导出结构化回执。回执包括版本号、全部科目、总价、条款、供应商声明、包标识和摘要；供应商自己保留一份。

导入时校验包归属企业、需求/轮次版本、邀请供应商、科目集合、金额格式、总价及重复回执。重复导入不产生第二份报价，版本不一致进入待处理队列；附件的文件名不作为唯一身份。

普通校验摘要只能发现传输损坏或不一致，不能证明供应商身份。身份要求较高时采用预登记的离线签名证书及验签流程，或保留带签章的确认件和人工核验记录；私钥不能预埋在公共 HTML 表单中。采购代录、文件导入、网页提交在每个回执上明确标记。

完全离线时没有可靠的第三方在线提交时间证明，先记录供应商声明时间和本机接收时间，按企业事先发布的文件回收截止规则处理。不能利用可修改的文件时间断言“按时提交”。

## 11 页面与数据对象

采购工作台：待发布、待回收、待开标、待确认目标价、待供应商回复、待处理变更；供应商页面仅展示对应任务。

需求编辑：货量/路线/时间/服务条件 + 费用科目表 + 可比口径；发布预览确认锁定版本。

供应商填报：需求摘要、逐项价格状态、报价条件、自动总价、声明与提交回执。

比价台：供应商 × 科目矩阵，完整整单价、分项参考组合、不可比提醒、原件与版本、排除理由；目标价编辑与审批为独立区域。

反向议价页：整单目标价与条款、接受/拒绝/附条件/重新报价、回复截止；供应商不可看到竞争者报价。

履约页：确认承接、计划与实际进度、退出事件、费用变更申请/批准/执行、结算引用；评估页支持按路线/货量/期间筛选并显示分母。

概念实体：PurchaseRequest、RequestVersion、CostTemplateVersion、CostItem、Supplier、SupplierInvitation、QuoteVersion、QuoteLine、QuoteReceipt、ComparisonRun、TargetOfferVersion、OfferResponse、AwardDecision、FulfilmentRecord、WithdrawalEvent、CostChange、SettlementReference、SupplierMetricSnapshot、AuditEvent。

每次 ComparisonRun 固定输入报价版本、口径、算法版本及排除理由；目标价修改生成新版本。所有企业业务对象带 tenant_id，供应商邀请权限只覆盖指定需求和自己的记录。

## 12 实施与验收

顺序建议：先交付无模型的询价/独立填报/回执/同口径比价/目标价确认，再交付反向议价、承接及变更评估，之后做 Windows 离线安装和恢复演练；离线报价包与网页入口共用同一套校验。可选 AI 最后接入，不能成为报价计算前置依赖。

验收至少包括：干净且断网的 Windows 电脑双击可启动；无额外运行时或数据库安装；断网完成一次文件交换报价闭环；局域网手机扫码只看到自己任务；空项不按零、包含项不重复计费；整单捆绑报价不被拆解；参考最低组合不被当作已成交；需求改版要求重新确认；重复导入/提交不重复计数；无权人员不能改供应商出价或查看竞争者；费用变更和退出原因可复核；备份在另一台干净电脑可恢复；采购电脑休眠时明确不能在线收件。

已确认：供应商联网填报，采购端允许联网同步，主数据本地保存。待确认：整单还是可分包、十个科目的真实定义、币种/税口径、截止规则、承接确认规则与独立审计保管方式。上述答案用于收敛设计，不默认授权任何对外发布或发送。

## 13 已确认的联网同步方案

### 13.1 系统组成与数据位置

采购人员双击本地客户端处理需求、比价、评估及历史记录；供应商使用浏览器打开公开门户的独立邀请链接。二维码指向门户域名，不指向采购电脑 IP。本地客户端只主动发起出站连接，无需供应商直连、固定公网 IP 或将本机管理服务暴露到互联网。

| 数据 | 本地采购主库 | 在线门户 |
|---|---|---|
| 企业内部需求、历史项目、成本、供应商评分 | 完整持久保存 | 不默认上传 |
| 已发布询价需求与费用模板 | 保存全部版本 | 仅保存供应商填报必需的发布版本 |
| 供应商报价与提交回执 | 同步后形成不可覆盖的原始记录 | 暂存正式提交及供应商可访问的自己的版本 |
| 比价过程、最低价来源、内部选择理由 | 本地计算和留存 | 不上传、不向供应商披露 |
| 已批准目标报价及必要条款 | 保存批准与发布版本 | 按邀请范围展示给对应供应商 |
| 接受、拒绝、附条件与重新报价 | 同步留存及评估 | 收件、回执与回复状态 |

在线门户是实际收件服务，需要鉴权、独立存储、备份和维护，不是一个无需后端的静态二维码页面。“主数据在本地”不等于“报价不经过线上”；如果未来要求服务端不可读取报价，需另行设计端到端加密、客户端密钥备份与收件验证，当前不作此承诺。

### 13.2 发布、回收与反向议价

本地需求草稿 → 人工批准发布 → 上传已冻结的供应商可见版本 → 门户确认发布成功 → 生成/启用独立邀请 → 采购人员分发。

供应商独立填报 → 门户校验需求版本、科目和金额 → 事务保存报价及回执 → 采购端拉取增量 → 本地事务入库并去重 → 向门户确认已落库。门户收件成功与采购端已同步分开显示，供应商不需等待采购电脑开机才能取得收件回执。

本地生成参考价 → 采购授权人确认目标价及完整条款 → 发布目标报价版本 → 门户送达供应商任务列表 → 接受/拒绝/附条件/重新报价 → 回流本地核验 → 选择完整可执行方案。

发布目标价的授权不自动授权发送任意外部消息。首期通过门户任务与可分发链接工作，采购手动分发；邮件/短信/聊天渠道接入以后单独设计。

### 13.3 断网、关机和一致性

- 采购电脑离线：可查本地历史、做草稿和已收齐数据的本地分析；不能显示新发布或已送达成功。待发布记录进入出站队列，恢复联网后再次核对版本和审批状态再提交。
- 采购电脑关机：门户继续接收有效报价和目标价回复，开机后同步。门户停机则明确无法提交，不把供应商浏览器的未发送草稿计为正式报价。
- 每个业务消息有企业、需求/轮次、供应商、版本、事件编号和幂等键。网络重试不重复生成报价、回复或评分样本；同步游标按成功入库事件推进。
- 供应商正式提交先在门户成为不可覆盖的收件事实；本地保留原始快照，采购只能追加核验、排除或选择记录。采购端与门户不是两个可任意覆盖同一报价的主库。
- 需求和目标价由采购端发布，报价和回复由供应商侧提交。对同一对象明确唯一写入方，冲突或旧版提交进入待核验队列，不采用简单的“最后更新时间覆盖”。
- 截止按发布的时区与门户服务端收件时间判断，冻结轮次形成已截止事件和报价版本清单；采购端确认收齐该清单后才能标为正式开标比价。未联网或未收齐时只能显示预览，不提前声称最终最低价。
- 第一版每个企业设置一个采购主库及发布主机；其他电脑需要访问它提供的内部服务或走受控迁移，不允许复制数据库后多台同时独立发布。换机应撤销旧设备发布凭据并恢复本地备份及同步游标。

### 13.4 留存、身份与验收补充

门户设置明确的数据留存期；本地确认同步不等于立即删除线上回执。应覆盖供应商自查、在途议价及争议核对所需期间，再由企业批准清理。在线备份的保留与清理也计入策略，不能删除主表后就称云端无记录。

各企业门户访问凭据与供应商邀请分离，本地同步身份只访问该企业数据；每个供应商只能访问获邀需求和自己的报价。邀请到期/撤销、重发、提交和下载均有记录。公开二维码不附内部原件、进货成本、竞争者名单或其他供应商报价。

补充验收：采购电脑关机仍能收报价；重试同步不重复；一条报价只有门户收件回执而未入本地时显示正确状态；未收到截止清单不得正式比价；旧需求/目标价回复不覆盖新版；另一供应商猜编号也无法读取报价；门户不可见本地最低价来源与评估；恢复备份后增量同步能校验并补齐记录；本地未批准的议价草稿不得上传为已发布。
