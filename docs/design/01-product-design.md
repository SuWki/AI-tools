# AI WorkHub 产品与业务设计

V3 设计草案 · 2026-11-05 · 首个试点为空压机外贸（用户已确认）

V3.1 补充：三企业专属场景与字段已扩展到 [三家企业业务设计](03-company-design.md)。Kotech、Warmpaca 和上海安特瑞商贸有限公司的企业差异以该补充文件为准；上海安特瑞资料待核实。

## 1 产品判断

平台帮助销售与技术人员协作处理有依据、可跟进的客户咨询。产品最重要的对象是一条持续更新的咨询工单：客户说了什么、哪些信息已确认、依据来自哪里、准备怎样回复、谁审核、何时继续跟进，都回到同一条记录。

现有项目已具备六页面、身份与企业隔离、工单、知识审核及人工复盘等基础。主要缺口在业务对象之间：清单未落为字段、模板未成为受审草稿、备注未成为任务。此次设计优先连接这些环节，并减少为一次工作在页面之间来回寻找信息。

## 2 首个试点与成功标准

空压机外贸：销售收到邮件或经授权的客户消息，手工录入原话，确认用途、工况与规格，寻找有效产品资料；一般澄清回复由销售确认，涉及具体技术选型、价格、库存或交期的承诺需由企业授权人员核验后对外使用。消息渠道只记录来源，第一阶段由员工在外部渠道发送。

试点业务负责人、技术审核人和报价授权人尚待企业指定；默认设计为技术审核角色核验技术项、管理员配置商务授权人，销售本人不能批准自己提交的高风险承诺。

首轮验收以一条真实但脱敏的典型咨询为单位：原话可追溯，必要字段有值或明确缺失状态，回复引用可用版本，人工确认与审批记录可追溯，下一步有负责人和时间，结案有结果。无 API 时以上流程必须成立。

## 3 范围与先后顺序

| 范围 | 首个可验收版本 | 后续增强 |
|---|---|---|
| 咨询处理 | 录入、分配、结构化需求、资料引用、草稿、人工审核、发送确认、任务、结案 | 消息同步、客户跨工单画像 |
| 知识 | 手工文本与链接录入、产品档案、来源、有效版本、审核、历史与失效提醒 | 文件上传解析、OCR、混合检索 |
| 模板 | 场景模板、占位字段、版本、企业规则、缺失信息提示 | 模型建议、自动填充建议 |
| 管理 | 成员邀请/停用、角色、业务配置、审计、受限导出 | SSO、复杂组织层级 |
| 统计 | 待办、逾期、阶段分布、计时记录及明确分母 | 可比较的业务收益实验 |

首轮不依赖模型 API、WhatsApp 集成、自动发送、自动报价、CRM、零部件图、3D 或大而全的经营看板。架构保留扩展位置，不在界面放置不可用的占位按钮。

实施依赖顺序（仅设计排期，不授权开发）：身份与租户上下文 → 工单及需求 → 知识版本 → 草稿审核及发送确认 → 任务及结案 → 配置、审计、统计与全流程验收。首轮发布须包含这些环节，不能只交付前半段后声称完整闭环。

## 4 信息架构

| 导航 | 使用者来这里完成什么 | 主要入口 |
|---|---|---|
| 工作台 | 找到今天该处理、待我审核或已逾期的工作 | 工单、任务、审核直接定位 |
| 客户咨询 | 登记和持续处理咨询 | 列表 → 工单工作区 |
| 产品与知识 | 查型号、看有效依据、维护和审核资料 | 产品档案、资料版本、审核队列 |
| 业务模板 | 查找和维护可复用回复模板、生成外部 AI 指令 | 模板库、场景、版本 |
| 复盘与统计 | 看结果与过程，落实改进任务 | 工单复盘、指标口径 |
| 企业管理 | 管成员、角色、规则、审核与导出范围 | 配置、审计、安全会话 |

跟进任务属于工单，在工作台统一汇总；审核入口按登录角色显示，同时保留工单内的审批记录。回复制作留在工单工作区，避免跳到独立工具页后失去上下文。

## 5 主流程与交接

| 步骤 | 输入和操作 | 输出及交接 |
|---|---|---|
| 登记 | 客户名称/代称、原话、渠道、主题、负责人；标记消息时间和引用来源 | 唯一工单；负责人收到待处理事项 |
| 确认需求 | 填字段，逐项设为待询问/客户已确认/内部核验/不适用；记录确认来源 | 缺失字段；可由缺失字段建立跟进任务 |
| 核查资料 | 按型号、属性、适用范围查企业资料，选有效版本 | 工单证据列表；无资料时提交资料缺口 |
| 准备回复 | 选语言与场景模板，填充已确认字段，保留缺失提示，编辑草稿 | 草稿版本、引用与承诺清单 |
| 人工审核 | 普通澄清由销售核对；承诺类按授权提交审核 | 通过/退回、审核人、意见、时间、被审核版本 |
| 发送确认 | 复制核准正文，在外部渠道发送，再登记实际发送时间与渠道 | 发送记录；复制只记为复制，不能自动视为已发送 |
| 跟进 | 设置动作、到期时间、执行人；完成任务后写结果 | 工单时间线；无人接手的事项可见 |
| 结案复盘 | 选择结果、记录结论，检查未完成任务和未完成审核 | 已结案工单；可选问题、证据、改善任务 |

工单允许反复经历确认、查资料和回复；页面步骤导航不强迫按向导直线前进。缺少选型参数不妨碍发送澄清问题，但必须阻止缺乏依据的确定性选型回复。

## 6 状态模型

### 工单状态与业务阶段

- 工单状态：待处理 → 处理中 → 等待客户 / 等待内部 → 处理中 → 已结案；已结案可由负责人或管理员重开，必须记录原因。
- 业务阶段独立保存：需求确认、方案核查、商务沟通、成交跟进。状态描述等待谁，阶段描述业务走到哪里，避免混用。
- 等待状态必须有原因和下一次检查任务；不允许仅因等待而永久从待办中消失。
- 结案结果：已成交、未成交、客户暂缓、无效/重复、已解答。未成交填原因；重复工单链接原工单。无效工单可免除规格完整性要求。
- 结案前处理所有未完成任务和待审草稿：完成、取消并填原因，或明确迁移到另一工单。不能静默取消。

### 回复与审核

- 草稿 → 待审核 → 审核通过 / 退回修改 → 已登记发送；普通澄清可以由销售自检通过。
- 审核通过绑定草稿版本、引用版本、已确认字段快照与承诺项。编辑正文、变更关键字段或引用后，原审核失效，生成新版本并重新校验。
- 复制核准版本时再次检查有效性。过期资料、停用资料或引用失效时，阻止复制为正式回复；允许继续编辑草稿并替换引用。
- 草稿可含未完成占位符；正式复制前须消除占位符。缺失字段以提问形式表达，不能补造参数。
- 自由文本中的风险识别仅为提醒，不能保证发现全部承诺。提交者必须主动声明技术、价格、交期、库存等承诺类别并人工核对，审核记录保留勾选结果。
- 复制前允许查看正文；未审核正文显示草稿水印和状态，禁止使用正式复制动作。正式回复正文不带内部备注、客户隐私扩展或审核批注。
- 已发送后发现错误：追加更正记录、创建纠正任务；保留原发送记录，不覆盖历史。系统不声称可以撤回外部消息。

### 任务与知识

- 任务：待办 → 已完成 / 已取消；逾期是依据时间派生的提示，不是用户手动设置的状态。重开任务保留原完成与重开事件。
- 知识：草稿 → 待审核 → 已发布 / 退回；已发布内容修改生成新草稿，旧有效版继续使用；发布新版本后旧版转已替代。失效、撤回立即停止作为新正式回复依据。
- 旧回复保留引用快照。新版本发布后未发送草稿需检查差异；原审批不能默认为对新版本有效。历史已发送记录只标记引用现已变化，不改写正文。

## 7 空压机需求配置

字段按场景展示，不要求每条咨询填写全套技术参数。数值必须有单位，频率、电压及压力基准不能靠默认值推断。以下均为字段设计，不是选型规则或具体产品参数。

| 字段 | 类型 | 澄清场景 | 技术方案场景 |
|---|---|---|---|
| 用途与现场工况 | 文本、信息来源 | 记录已知信息 | 必须确认 |
| 工作压力及基准 | 数值+单位+表压/绝压 | 可未知并提问 | 必须确认 |
| 所需气量及计量条件 | 数值+单位+条件说明 | 可未知并提问 | 必须确认，不能混用不同计量条件 |
| 供电 | 电压、相数、频率 | 可未知并提问 | 必须确认 |
| 使用时长/负载、空气品质 | 枚举+说明 | 按需 | 按适用规则要求 |
| 安装环境及限制 | 文本 | 按需 | 由技术审核人判断是否足够 |
| 目标国家/地区、认证要求 | 文本+确认状态 | 按需 | 对出口方案核验 |
| 采购数量、期望时间 | 数量+单位、日期/描述 | 可未知 | 商务沟通前确认 |
| 客户提及型号 | 型号引用或原文 | 可选 | 不等于内部已批准选型 |

每个值保存确认状态、来源消息/资料、确认人及确认时间；修改保留历史。“不适用”需要说明，不能用来绕过必要校验。重要技术字段的不适用需要技术审核批准。

润滑油与羊驼工艺品的场景、字段和审批已在 V3.1 企业设计中具体展开；企业实际目录、内部授权和条件必填仍需业务确认后冻结。

## 8 权限及协作

权限由动作与数据范围共同组成。以下为首轮默认，企业可收紧；管理员不因角色自动成为技术或商务审批人。

| 动作 | 销售/客服 | 技术审核 | 管理者 | 企业管理员 |
|---|---|---|---|---|
| 工单与客户原话 | 本人负责/明确协作的工单 | 指派审核的工单及必要上下文 | 默认汇总，明细需单独授权 | 企业内管理权限，敏感读取留审计 |
| 草稿/任务 | 在可访问工单内编辑与处理 | 审核、退回、技术意见 | 只读授权明细 | 分配、移交、管理 |
| 产品知识 | 查看已发布资料、提交草稿 | 编辑与批准，关键资料避免自审 | 查看有效知识 | 配置审核规则、撤回 |
| 技术/商务承诺批准 | 不自批高风险承诺 | 技术类；商务另需授权 | 仅经明确授权的类别 | 仅经明确授权的类别 |
| 导出 | 默认禁止批量导出 | 默认禁止批量导出 | 默认仅汇总 | 按企业策略授权明细并记审计 |
| 成员/模板/字段配置 | 无 | 技术规则提出修订 | 查看 | 管理、发布版本 |

首期数据范围采用本人负责、明确协作、受指派审核及企业级授权，不引入复杂部门树。审核完毕后保留结果引用，不默认永久开放整个客户档案。邀请、角色变化、成员停用均留审计；停用前必须移交未完成工作。

租户上下文同时包括企业、用户、角色、数据范围和会话。切换企业只影响当前会话；同一 token 的其他标签页应收到上下文变化并清空旧企业缓存、返回新企业工作台；独立设备会话不受影响。切换期间有未保存内容时先保存或明确放弃。旧上下文发出的迟到响应不能显示到新企业，写入必须携带预期企业上下文，不一致拒绝并提示重载。

退出撤销当前会话；会话到期拒绝所有业务访问；过期时间由企业策略配置。成员权限变更对后续请求生效，不能只隐藏按钮。所有明细读取、引用、审核、导出、计时及文件链接都验证企业与数据范围。

## 9 领域数据设计

概念模型用于约束设计，尚不建立数据表或迁移脚本。所有企业业务实体带 tenant_id，外键关联也必须在同一企业内。

| 实体 | 核心信息与约束 |
|---|---|
| Enterprise / Membership / Session | 企业、有效成员/动作权限/数据范围、会话身份和失效；会话独立切换 |
| Customer / Case / SourceMessage | 客户轻量档案、负责人/协作人/阶段/状态/结果；原话及来源消息保留，不随界面语言改写 |
| FieldDefinition / RuleSetVersion / FieldValue | 类型/单位/条件必填、版本、逐工单的值和确认来源；在途工单固定规则版本，升级时显式迁移 |
| Product / KnowledgeItem / KnowledgeVersion | 型号与属性、来源、正文快照、适用范围、有效期、审核人与审核时间；发布版本不可覆盖 |
| Template / TemplateVersion | 场景、正文、占位符、输出语言和发布历史；工单固定使用的版本 |
| ReplyDraft / ReplyVersion / EvidenceLink | 每版正文、生成方式（人工/模板/外部 AI）、字段与资料快照、承诺类别 |
| Approval / DispatchRecord | 审核对象的精确版本、结果/理由；人工发送登记的渠道、时间、登记人和纠正关系 |
| FollowUpTask / WorkSession | 动作、执行人、到期时间/时区、结果；人工工作计时段及修正原因 |
| Review / ImprovementTask | 工单、问题、证据、建议、责任人、到期时间，可关联现有任务 |
| AuditEvent / ExportJob | 操作对象和版本、人员、时间、变化摘要；导出申请范围、字段、结果及审计 |

客户消息、内部备注、需求确认、正式回复、人工复盘分开存储与展示。审计摘要避免重复存储整段客户隐私；高风险读取和导出单独记审计，审计查看本身需权限。

并发编辑使用版本号：保存时如内容已变更，显示两版差异，让用户选择合并，禁止静默覆盖；新增任务、发送登记及审核动作需防重复提交。

## 10 统计口径

| 指标 | 定义 | 展示限制 |
|---|---|---|
| 我的待办/逾期 | 当前用户未完成且可访问的任务；due_at 早于当前时刻为逾期 | 与全企业任务分开，不混入他人无权限事项 |
| 待审核 | 当前用户有审批权且尚未处理的精确版本 | 同一草稿版本按待审批事项计数 |
| 工单状态分布 | 当前筛选企业、范围和期间内创建的工单，按当前状态分组 | 显示时间范围与分母 |
| 首次回复等待时长 | 登记时间至首次登记发送时间的自然时长 | 等待时间不称为人工处理耗时 |
| 实际处理耗时 | 员工主动开始/暂停的有效工作时段之和，含核对审核；允许修正并留理由 | 无计时数据标未记录；展示有效记录覆盖率，不用创建到结案代替 |
| 需求遗漏率 | 抽查中漏掉场景必填字段的工单数 / 被检查工单数 | 与未填但已明确待询问区分，由审核人认定遗漏 |
| 资料查询成功率 | 主动登记找到适用已审核依据的查询次数 / 登记查询次数 | 未审核资料不计成功；显示为自报数据 |

计时不是员工监控：不采集键盘、截图或页面停留来推断劳动。离开时提示暂停；遗忘计时允许人工修正。对比原流程收益需要同类任务基线，未完成试验前不显示节省比例。

## 11 多语言与视觉原则

首期完整中文与英文 UI；客户原文、内部备注、字段值保持原样。回复语言独立选择，切换 UI 不翻译或重生成草稿。产品名缺英文版时保留原名并显示“原文”，未经审核译文不能冒充已发布内容。

日期按用户 locale 展示，任务同时记录时区；跨时区查看显示查看者本地时间及原始任务时区。金额强制明确币种；数值字段单位与值成组，不能丢失。错误返回稳定错误码并映射界面词条，不直接露出内部异常英文。

沿用原项目深蓝侧栏、青绿色主动作与浅背景，减少大面积营销卡片。工单采用主内容加证据侧栏，先显示下一步动作，再展示完整历史。状态使用文字和图形共同表达；审核与失效警告靠近操作。正文桌面 14–16px，输入和长回复保持可读；键盘可完成表单、弹窗和审核，窄屏将侧栏改为单列区块。

## 12 验收与待定事项
