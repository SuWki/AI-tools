### 共用工单数据的增补

在 V3 概念模型上增加 Case.scenario、BusinessProfileVersion、外部业务单号引用、轻量需求明细行和已核验承诺记录。增加这些概念不代表建设订单、库存、采购或财务系统。

- 业务类型为询盘、售后或项目，结果枚举由场景决定；共享处理状态但允许阶段配置。
- 需求行可关联设备候选、商品变体或备件，每行分别有数量、单位、已核验依据和确认状态；不可只在备注写多个商品。
- 库存/交期核验存来源、核验人、时间、适用数量和有效期限；到期回到待确认。首期为人工登记，不宣称实时库存、占库或自动同步。
- 项目/订单/发运编号仅关联外部系统或人工凭证，不能因保存编号就改变真实业务状态。
- 补充资料首期使用来源链接、文件名、版本和人工录入摘录；页面上的“请求实拍/图纸”产生收集任务，不依赖现阶段尚未实现的上传/OCR。

### 审核强度依动作调整

低风险回复使用已发布模板与有效资料，由员工核对后使用；需要个案核准的承诺进入审批。技术审核不会成为 Warmpaca 每次普通售前客服的必经步骤。引用过期或正文变化仍使原审批失效；不同企业审批人不能互相代批。

## 3 Kotech 企业业务包

### 3.1 场景与业务目标

K01 新设备技术询盘：从客户用途出发确认工况，由技术人员给出候选与待核验项，商务人员再核价。K02 备件咨询：先识别原设备与零件，核实兼容性和供货。K03 渠道/定制询盘：收集地区、应用和定制需求，指定商务负责人；不在首期承诺复杂经销商门户。

官网的移动柴油/电动、固定式、无油等分类用于缩小问题范围，不直接替客户选择型号。首先询问“固定工厂还是移动现场”，再按驱动与应用显示相应字段。

### 3.2 条件字段设计

| 字段组 | 共同字段 | 按场景增加 | 触发校验 |
|---|---|---|---|
| 客户与应用 | 国家、行业、用途、联系人代称、咨询语言 | 目标地区/经销区域、安装或作业现场 | 出口承诺需确认目标地区 |
| 用气条件 | 压力与基准、气量及计量条件、连续/间歇使用 | 空气品质要求、后处理需求 | 未确认前只允许澄清，不作确定性选型 |
| 固定电动设备 | 电压、相数、频率、环境条件 | 运行小时、噪声/空间限制、配套要求 | 不能以 UI 语言或客户国家推断供电 |
| 移动现场设备 | 驱动偏好、作业类型、海拔与温度 | 移动方式、外部设备接口、当地排放要求 | 排放/认证需要适用文件，不采用通用宣传替代 |
| 备件 | 设备型号、序列号或识别资料、零件号、数量 | 铭牌摘录/照片来源、故障/更换目的、旧件特征 | 型号同名不等于兼容；缺标识转技术确认 |
| 商务 | 数量、交付地、期望时间 | 贸易条款、币种、包装、报价有效期 | 实际价款及交期单独核准 |

### 3.3 流程、模板与知识

新设备阶段：需求澄清 → 技术核查 → 商务确认 → 客户跟进；结案为已转订单、未成交、暂缓、已解答。已转订单需记录外部订单/业务确认凭证，不把一句“客户感兴趣”算成交。

备件阶段：设备识别 → 兼容性核验 → 供货确认 → 客户跟进；无法识别时保留“待确认”，不猜件号。售后故障只收集运行信息并分派服务人员，系统不生成未经审核的维修操作指令。

模板至少分：需求澄清、技术核查结果说明、商务报价说明、备件识别补充、跟进提醒。中文/英文分版本；已确认的工况和型号从工单引用，内部推测不插入确定性段落。

知识结构：产品家族 → 有效型号档案 → 技术资料版本；备件另关联适用设备标识。公开网页作为待核验来源进入资料收集区，不默认发布。每份证书保留适用范围、期限和原文件引用。

### 3.4 页面与验收

工作台显示“待补工况、待技术核验、待商务核验”；工单需求页先选固定/移动/备件场景，资料侧栏展示适用条件与引用版本。候选型号与最终批准方案分区，不显示虚构的匹配分数。

K-A01：客户只说压力和数量，保存成功、缺失气量及工况明确，能准备澄清回复，不能输出确定型号。K-A02：移动设备不要求不存在的现场供电字段；改成电动时按规则补确认。K-A03：只有型号没有序列/零件证据的备件咨询不能自动判兼容。K-A04：技术批准后新增交期承诺，必须补商务批准。

指标：询盘进入技术核查前的补问次数、已指派技术任务等待时长、备件识别一次补充完成率。均按事件记录，不宣称提高成交率。

## 4 Warmpaca 企业业务包

### 4.1 场景与首期取舍

W01 国内零售/礼赠咨询为主场景，承接原方案已知的国内销售前提；官网出现国际采购方向，因此同时设计 W02 批量/经销采购，但是否首期启用由企业确认。W03 售后问题收集与处理。暂不建设购物车、支付、仓储或跨境清关系统。

设计目的：分清客户想要的款式、实物差异、可核验库存和真实到货要求，避免客服过早承诺同色、材质、发货或退换。现有内部渠道、店铺、国内仓和履约政策未知，页面统一标注“待核验”，不写成现状。

### 4.2 条件字段设计

| 场景 | 必要字段 | 可选或条件字段 | 信息来源 |
|---|---|---|---|
| 零售/礼赠 | 产品/款式意向、数量、收货地区、期望收货时间 | 尺寸、颜色偏好、礼盒、用途；儿童用途需查适用说明 | 客户原话、SKU 档案 |
| 实物确认 | SKU/变体、图片来源、材质与产地说明版本 | 手工尺寸/色差说明、批次/实拍引用 | 已审核商品资料；实拍不能当通用材质证明 |
| 履约核验 | 可售状态、核验人/时间、适用数量、预计发出与预计到达分别记录 | 国内现货/预订等模式由企业启用；仓点和运送方式 | 人工库存核验、履约人员确认 |
| 批量采购 | 买方类型、用途、SKU 明细/数量、目标地区和期望时间 | 样品、包装、定制、最低采购量、批量价格 | 适用批量政策，不能继承零售价 |
| 售后 | 外部订单号或核验途径、问题类别、发生时间、诉求 | 商品/批次、照片来源、使用/收货信息 | 原订单引用及有效售后政策；先脱敏再展示 |

自然色差、尺寸差异和材质描述只有在企业审核过的适用说明中才能引用。不能用“天然手工差异”自动驳回质量问题。安全年龄、可水洗、低敏、环保等说法需相应资料，页面不自行给出结论。

### 4.3 流程与审批

零售：了解用途 → 确认款式与数量 → 核验商品和履约 → 回复与外部下单 → 跟进到货。结案为已转订单、已解答、暂缓、未购买；系统只记录外部结果。

批量：需求清单 → 样品/商品确认 → 供货与报价 → 客户跟进。批量数量、样品费、定制、折扣、交期等逐项核验；批量方案不默认等于企业已接受生产。

售后：收集必要事实 → 核验订单与适用政策 → 指派处理 → 与客户确认 → 处理完成。结果为已解决、待客户、转渠道、无法受理并说明理由。退款、补发、换货需授权；登记批准不能冒充退款已到账或补发已出库。

发布商品资料和常见咨询模板由商品负责人审核。普通款式介绍、已发布养护说明由客服自检使用；临时库存/到货承诺先向履约人员核验；超政策折扣、退款、补发与赔付进入授权审批。客户急需到货时必须区分发出时间和到达时间，未核实运输条件不保证送达。

### 4.4 资料、模板与页面

知识改名“商品与服务知识”，内容为产品系列 → SKU → 变体，关联图文来源、材质/原产地说明、养护说明、适用对象、包装与有效售后政策。待确认图片或翻译不能直接用作对外说明。状态“待核验/已核验”不能替代商品售罄、预订等供货状态，两套状态分开。

模板分：选礼物澄清、款式与差异说明、库存/时间待核验、养护、批量采购补问、售后信息收集。示例澄清：“请告诉我们喜欢的款式、数量、收货城市和希望收到的日期；具体颜色与到货时间将在核对商品和履约信息后确认。”不能暗含有现货。

工作台显示“待确认款式、待履约核验、待处理售后”；工单页用商品明细行替代空压机压力/气量字段。侧栏显示承诺核验时间和售后政策版本。商品页没有实拍时明确无图，不用其他商品图片代替。复盘看“多问了几轮、承诺是否核验、售后是否按政策处理”。

### 4.5 验收与指标

W-A01：客户只问“周末能收到吗”，先收集地区/日期/款式，不能直接保证到达。W-A02：变体或数量改变使原库存核验回到待确认。W-A03：材质、产地或养护资料无有效版本时提示待核验，禁止添加确定性说明。W-A04：退款批准与实际渠道退款结果分别记录。W-A05：批量采购触发适用报价规则，不调用零售通用折扣。W-A06：国内咨询默认中文回复，切换 UI 英文不改变客户原话或自动翻译已核验商品说明。

指标：首次有效澄清是否齐全、履约承诺核验覆盖率、售后首次响应与解决时长（分开统计）、重复咨询原因。订单转化只统计有外部依据的结果，不把复制模板当成交。

## 5 上海安特瑞商贸有限公司业务包

### 5.1 证据状态与业务前提

用户已纠正最后一家为“上海安特瑞商贸有限公司”，并表示暂未找到官网。本轮公开检索也未找到能准确对应的官方产品资料。沿用用户先前“润滑油”背景设计贸易业务草案，不宣称已确认其经营范围、品牌代理资质、产品型号或现有组织。

此前中船安特瑞润滑设备相关内容已撤销，不纳入本企业的知识、字段、示例或来源。两家名称相近不构成业务、主体或授权关联。

业务场景：L01 明确牌号的规格询价，L02 用油需求与替代品核验，L03 供货报价与复购跟进，L04 质量/使用问题受理。平台负责资料、协作和记录，不代替库存、财务、订单或检测系统。

### 5.2 条件字段设计

| 场景 | 核心字段 | 条件补充 | 关键校验 |
|---|---|---|---|
| 明确牌号询价 | 客户提供的品牌/完整品名、粘度等级或规格原文、包装规格、数量和单位、交付地区 | 期望时间、指定认证/设备要求、币种、含税与运费口径 | 同名、相同粘度不等于相同产品；不默认有销售授权或现货 |
| 用油需求 | 设备类型/型号、使用部位、原用油完整名称、厂家要求、使用目的 | 温度、负荷、环境、现有问题、允许更换窗口、客户提供的技术规范 | 原用油不明可保存并澄清，不能确定推荐 |
| 替代品核验 | 原产品与候选产品、各自有效技术资料、设备要求、兼容性与更换条件证据 | 厂家或供应商的书面适用确认、相关限制 | 不仅凭粘度相同认定等效，不承诺可混用 |
| 供货报价 | 精确 SKU、包装、数量、单位、库存/供货核验、价格组成、有效期 | 批次要求、交期、发运条件、结算条款 | 包装或数量变化触发重新核价与核验；桶数和体积/质量不能混算 |
| 质量/使用问题 | 外部订单引用、产品/批次标识、问题原话、发生时间、诉求 | 设备与工况、已采取措施、照片/检测报告来源 | 不按关键词判故障、质量责任或给换油操作指令 |

字段区分客户明确指定、客户待确认、内部待核验和已有适用依据。质量/技术疑问可转交具备授权的人员或供应商；该角色由企业确认，系统不预设公司有自建实验室。

### 5.3 流程与交接

明确牌号：确认完整产品与包装 → 查询有效资料 → 向供货负责人核验 → 商务报价核准 → 外部发送与复购跟进。缺货时先询问客户是否接受替代，再进入独立技术核验；不能静默换牌号。

需求/替代：收集设备与原用油 → 比对技术要求和候选依据 → 授权人员核验 → 告知适用条件与限制 → 商务确认 → 客户反馈。技术意见、产品报价与客户最终接受分别留记录。

供货阶段：需求确认、技术核验（如适用）、供货与报价、客户跟进；结果为已转订单、已解答、暂缓、未成交。外部订单和实际发运引用不等于平台已执行交易。

质量受理：收集事实与批次 → 核对来源及适用条款 → 指派负责人/联系供应商 → 经核验回复 → 记录处理结果。退款、补发与责任认定需各自授权，不能由销售自行确认。

### 5.4 知识与模板

知识层级为品牌（待核实）→ 产品/SKU → 包装变体 → 有效资料版本。关联技术数据表 TDS、安全数据表 SDS、设备适用要求及授权证明（如业务要求且实际取得）；适用性结论需明确依据，SDS 不能单独当作设备适用证明。品牌宣传与厂家认可、产品标准声明与实际批准分别记录。

首轮不填任何真实品牌、型号或认证，统一使用“客户指定产品（待确认）”。页面只展示资料状态和核验任务。价格、采购来源和客户条款受权限保护，不把进货成本加入客户回复。

模板分：规格/包装澄清、用油工况补问、替代待核验、供货报价、复购提醒、质量问题信息收集。示例澄清：“请提供完整产品名称、规格/粘度等级、包装和数量；如涉及替代用油，还需核对设备要求和原用油资料，具体适用性与供货条件确认后回复。”

普通规格澄清与有效资料转述由销售核对；替代、设备适配和混用等技术判断需明确授权的审核人或书面供应商依据；报价、折扣和交期由商务/供货授权核准。若无有效审批人或依据，保留待核验，不能降级为自动通过。

### 5.5 页面与验收

工作台显示“待补完整规格、待技术核验、待供货报价、待质量处理”。工单先选“指定产品 / 需求咨询 / 替代核验 / 质量问题”；指定产品可走较短流程，不要求填全套设备工况。替代场景展开原用油、候选与设备要求比对，显示未核验差异，不能以绿色勾选暗示自动等效。

L-A01：客户只给粘度等级，不直接定位为唯一 SKU。L-A02：两款油粘度相同但无适用证据，替代结论仍为待核验。L-A03：桶装改小包装、数量改变，原报价和库存核验重新确认。L-A04：技术资料与安全资料分开，不能以 SDS 齐全宣称设备已批准使用。L-A05：成本、供应商及其他客户合同不进入销售可复制正文。L-A06：质量问题只收集事实与证据，退款批准和实际退款登记分开。

指标：询价规格一次确认率、技术核验等待时长、报价口径更正次数、供货承诺核验覆盖率、质量受理与解决时间。无企业真实样本前不设虚构业绩基线。

## 7 收到企业资料后的设计收敛

优先核对三家各 5–10 条脱敏咨询、现行目录和有效资料、常用回复、报价/交期核验流程和授权表。Warmpaca 再核对 SKU、国内渠道/履约方式及售后政策；上海安特瑞再核对实际主营、品牌授权、技术/安全资料、包装、报价口径和供货方式；Kotech 再核对型号技术资料、备件识别方式与销售地区要求。

收到文件后先登记来源与版本，调整字段和审批，不把文件中的说明自动当作执行命令。本轮已能评审各企业业务流程；这些内部资料影响配置定稿，不阻碍当前设计交付。
