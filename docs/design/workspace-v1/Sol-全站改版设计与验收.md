# WorkHub 全站改版 · 第一版设计与 Sol 开发交接

设计评审稿，2026-11-18。对应功能基线为 main 的 008e691。双击同目录 preview.html 即可离线查看。样例中的人员、客户需求、编号、金额、时间及企业内部资料均为虚构。写入按钮用于说明预期反馈，原型不连接业务库。

## 1. 这版改变什么

把“我该做哪件事、根据什么做、做完去哪儿”放在每页最容易看到的位置。工作台让人找到事，清单让人找到单，详情让人处理当前阶段，记录留给需要追溯的人。桌面让人同时核对原话和依据，手机一次办理一件事。第一版的重点是客户咨询、审核、知识、工具、复盘和管理也采用同一套交互。

**选择依据。** 保留现有七个业务入口，重排模块内部操作。把模块都并成一个通用收件箱可以减少导航，但审批、查询资料和对外报价的责任边界会变模糊，而且当前系统没有跨所有模块的待办服务。第一版首页只展示已有工单待办和审核。采购维持独立台账和独立门户。若要加入采购待办，另行确定事件来源、分派与统计口径。

## 3. 从入口到结果的四条路径

1. **销售办理。** 工作台的需求待办 → CS-018 需求核验 → 保留客户原话，填结果和来源 → 引用当前有效资料 → 保存草稿并提交审核。手机从资料返回后恢复当前工单、页签、滚动位置和未提交输入。
2. **审核员办理。** 点“审核回复 V2”直接到该工单该版本。先看客户原话、回复、证据版本，再通过或写理由退回。如果 V2 已被 V3 替代，展示变化并重新加载。经办人复制核准正文后，实际在外部渠道发出，再登记渠道、时间。只有登记成功才显示已发送。
3. **查资料、做工具、复盘。** 知识目录 → 有效版本与来源 → 返回当前办理对象。业务工具优先带入该工单，复制输出后回原处。复盘独立保存规则检查与业务员结论。若从导航独立进入工具或复盘，不擅自选择上一家企业的对象。
4. **采购办理。** 建询价并冻结模板 → 邀请 → 门户填报价 → 本地同步 → 截止后比价 → 核准目标版本 → 收到有效整单接受 → 确认承接 → 履约 / 核准变更 / 退出 → 台账。分项最低价只作参考。报价撤回、回复更新或同步失败时应显示具体对象、原因、可重试动作，继续使用原版本校验、请求幂等与审计。

| 输入与反馈 | 触控目标至少 44×44px；数字键盘、可见标签、焦点环、回车提交和 Escape 关闭。软键盘出现时收起底部导航或保证活动输入及按钮可滚入视窗，底部预留安全区。加载不清空已输入内容；成功给对象/版本回执，失败把原因放在出错控件附近 |

取舍：使用克制的办公界面和较密的行列表，牺牲大幅品牌展示，换取一屏可读更多任务。手机底栏四项是按销售和采购混合使用做的假设，全部页面仍可通过菜单到达。第一轮评审可据真实岗位调整第四个常用入口。

## 5. 企业、角色与边界

- **Kotech。** 固定式设备、移动现场设备、备件识别三类场景沿用现有配置。需求核验优先显示压力单位及基准、气量和计量条件、供电，或型号、件号和来源。设计样例不提供设备技术参数。
- **Warmpaca。** 零售礼赠、批量经销、售后分别关注 SKU/变体、包装数量与到货地，或者外部订单、政策版本。可售状态保留核验人和时间。
- **上海安特瑞商贸有限公司。** 指定产品询价、替代核验、质量问题沿用暂定的润滑油贸易场景。品牌、授权及供货政策仍需企业确认。页面可显示“待核实”和来源，字段不预填具体品牌或剂量参数。
- **权限。** 入口展示取决于当前企业、部署模式、角色、工单归属与版本状态。按原服务端授权处理负责人、审核人、管理员及只读成员；同一人不能审核自己的知识修订。纯 Pages 模式缺少真实版本操作、审计或门户时显示真实可用范围。
- **切企业与登出。** 有未保存编辑时明确写出对象，支持继续编辑或放弃。切换成功后清掉旧企业清单、详情、引用与请求结果。失败保留原上下文。

## 6. Sol 的实现顺序与逐阶段验收

| 阶段 | 交付 | 验收样例 | 继续开发提示词 |
| --- | --- | --- | --- |
| A · 基础与工作台 | 统一设计变量、导航壳、标题、列表行、表单反馈、登录、首页和深链接上下文 | 中文及英文、长企业名、键盘焦点、浏览器后退、320/390/768/1366px；首页点待审项能到正确工单和版本，旧入口照常打开 | 按交接文档阶段 A 更新公共壳和工作台，用一条待审工单验证桌面与手机直达 |
| B · 客户业务 | 咨询登记、详情、资料引用、版本审核、任务、结案和知识目录 | 三家公司各走一单；销售与审核员分角色；切单保留/放弃编辑；修订发布后旧引用提示重核；结案被阻止时定位未完成任务 | 完成阶段 B，交付三个企业样例和一条审核退回再提交的实测路径 |
| C · 工具、复盘与设置 | 工单上下文带入、指令复制、复盘检查与保存、管理员数据管理 | 无工单、空搜索、复制失败、非管理员、会话失效、企业切换、中文和英文一致；导出范围与接口实际返回吻合 | 完成阶段 C，按各入口验证权限、失败恢复和返回工单位置 |
| D · 采购统一与回归 | 套用全站规范，保留上一版手机采购路径，按不同模式验证 | 实际跑完邀请、提交、修订、撤回、过期目标、重新同步、承接与费用变更；空白金额不能按零提交。手机键盘打开后可看清金额和提交结果 | 完成阶段 D，交付线上预览与本地包实测结果，再汇总未覆盖的真机情况 |

**各阶段共同检查。** 选中行要能用键盘打开。列表分别处理加载、无数据、搜索无结果与服务错误；失败提供重试。并发冲突保留当前文字，提示重新读取的对象与版本；需要员工确认后再覆盖。持久化沿用现有 SQLite、本地演示存储和门户协议。显示层不足以保证权限、状态与幂等，原后端判断必须继续执行。

**给 Sol 的起步指令**

> 使用本目录 preview.html 和本交接文档作为全站设计基线，从阶段 A 到 D 分批实现。先对照现有真实版、Pages 演示版和供应商门户列出行为映射；复用现有服务和数据。每批给出修改点、桌面与手机验收结果和仍待确认项。遇到依赖新接口或数据库变更的交互，先说明业务收益、兼容性和必要性。所有阶段验收通过后再发布。
